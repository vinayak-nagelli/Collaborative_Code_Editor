[8] 1. Executive Summary
[9] Current state: The uploaded ZIP contains a working MERN-based collaborative IDE foundation. The README explicitly marks authentication, dashboard, project/templates, file CRUD, Monaco editor, Socket.IO rooms, Yjs CRDT collaboration, presence, invitation links, terminal execution, search, source control, command palette, themes, version history, security/rate limiting, keyboard shortcuts, diagnostics and breakpoints as implemented. The debugger and extensions marketplace remain incomplete/mock components.
[10] Direction proposed in this plan: Keep the collaborative IDE as the core, but extend it into a collaborative engineering platform connecting requirements, tasks, coding, code review, testing, bugs, communication, contribution evidence, project health and AI.

[50] 8. Recommended Roadmap Based on the Current Implementation
[51] The sequence below avoids rebuilding the project. It starts from the existing working collaboration core, closes current gaps, then adds product features in dependency order.
[53] 8.1 Feature Dependency Order
[54] Keep the current collaborative IDE stable: authentication → project/files → CRDT collaboration → terminal/Git/version history.
[55] Add requirements and tasks so there is a clear unit of work to connect to code.
[56] Add review and QA so a code change can be linked to verification.
[57] Add contribution/analytics only after work items and change history exist as reliable evidence.
[58] Add AI using the project graph and existing diagnostics/version information as context.
[59] Add communication and resources around the same project/task objects rather than as an isolated chat app.
[60] Add deployment/CI-CD after build and test results are trackable.
[61] Add SaaS/multi-tenant/billing features only after the engineering workflow itself works well.
[62] 9. Recommended Final-Year MVP vs Later Startup Scope
[64] 10. Practical Implementation Guidance
[66] Frontend: create pages/components for requirements, tasks, QA, dashboards and AI panels; connect them to the existing API and socket services.
[67] Backend: create routes/controllers/services for each new domain; keep authorization on the server; do not trust role or ownership decisions from the browser.
[68] Database: add new collections/models only when the feature has persistent project data. Avoid storing transient cursor/presence information unless it is needed for analytics.
[69] AI: start with a simple provider-backed service and project context selection. Add a separate vector database only when the basic retrieval flow is proven to need it.
[70] Analytics: prefer evidence derived from project events (tasks, code changes, reviews, tests, bugs) instead of manual “productivity” scores.
[71] Security: before public exposure, replace credential-embedded Git remotes and upgrade terminal execution from process allowlists to per-project container isolation.
[72] 11. Final Project Direction
[73] Working concept: CollabIDE as a collaborative engineering workspace — not only an online code editor.

--- TABLE 7 ---
Gap | Why it matters | Action
Debugger backend | Current UI is only a shell. | Implement a real debug adapter/backend; connect execution, breakpoints, stack, variables and watch.
Extensions marketplace | Install/uninstall is mock/local state. | Replace mock behavior with a defined extension model, or explicitly keep it as a future phase.
Git authentication | Credential-embedded HTTPS URLs are not production-safe. | Move to a safer secret-management/auth approach before public use.
Search replace-all consistency | REST replace-all can conflict with an open live Y.Doc. | Route changes for collaboratively open files through the CRDT path.
Deleted-file source-control visibility | Deleted File records are hard-deleted. | Track deleted files or use soft-delete so source control can show D entries.
Terminal isolation | Current allowlist/no-shell/timeout model is for a trusted-user MVP. | Use per-project containers before supporting untrusted public workloads.
Bundle performance | Monaco/Yjs creates a large frontend bundle. | Add code splitting/dynamic imports in a later performance pass.
